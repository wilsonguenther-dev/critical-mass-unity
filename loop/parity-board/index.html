Now building in Unity

Updated 9:16 pm Central, Wednesday Nov 11, 2026 · Unity repo commit 6593701

What changed

The game is being rebuilt in Unity, the game engine (the software studios use to build and ship games) that Max works in. The browser demo is frozen: nothing new goes into it. It is now the rulebook and the test reference, so the Unity game has to play by the same rules and pass the same tests.

The new code lives at critical-mass-unity on GitHub. The controls and Max's list of game items are in MAX-ITEMS.md.

What exists tonight

An empty Unity project that compiles, runs its tests and produces a Mac app. Nothing of the game is built in it yet, so every row below says Not started in Unity. The browser captures and Claude's browser scores stay inside each row, boxed and marked "Browser demo, archived 2026-11-09", for comparison only.

The plan, in four phases

  1. Phase 0, foundation. Game rules, ground, pathing, base rules, bots, controls, a placeholder view and a test runner. Done when a full 16 versus 16 bot match plays start to finish in grey-box (plain shapes, no art) and every test carried over from the browser demo passes.
  2. Phase 1, mechanics. Max's items, starting with Travis's four must-haves: dig and place ground, knock down structures, jumping, and crossing bridges diagonally.
  3. Phase 2, look. The shared toon shader first, then the bible rows in this order: p05 colour and type, p06 Warrior, p07 Farmer, p08 Miner, p09 animation set, p10 and p11 Kaiju, p12 and p13 map, p14 props, p15 HUD, p04 logo and title, p03 overall look. A row is finished when it passes the team's score (see How a row passes).
  4. Phase 3, finish. Effects, audio (the 42 free sounds), menus, and a Windows build for Travis.

Phases 1 and 2 run side by side once Phase 0 is done. The plan writes down a finish line for Phase 0 only; the finish lines for Phases 1 and 3 get set when Wilson approves the plan.

How the look gets made

Every model uses one shared toon shader. A shader is the small program that decides how a surface is coloured and lit. This one gives flat bible-palette colours, two bands of light and shadow, a dark outline, a team-colour channel and a rim of light so each team reads at a glance. Nothing shiny or metallic. Until the art arrives, mechanics work uses team-coloured capsules and cubes, so gameplay never waits on art.

All three classes share one rig, the skeleton of joints a model moves by: the free KayKit rig with 41 joints, so all 76 free animation clips work on every class. Each character is sculpted by hand in Blender to its bible page, and its source file is kept in the repo. No script-generated stand-in bodies: those scored 3 to 4 in the browser.

Open point, the Warrior: Max's Blender Warrior is the starting mesh if his file passes an audit (it has to fit the shared rig and have clean geometry). Either way the Warrior gets the five corrections bible page p06 needs:

  1. A round shield, the class identifier, never removed.
  2. A stone cleaver with a glowing edge.
  3. A dark-brown topknot tied with a brass ring.
  4. Grey stone armour with cyan cracks.
  5. Flat toon shading.

How a row passes now

Each row gets a fixed set of framings: the bible's own poses and camera angles. A script renders every framing from the actual Unity build on a Void Navy ground and runs three measured checks:

  1. Colour. Each named bible colour on that asset is within 10 on CIEDE2000, a standard score for how different two colours look to the eye (lower is closer).
  2. Shape. The character's outline overlaps the outline in the bible drawing by at least 85 percent.
  3. Required features. Every item on the row's checklist, for the Warrior the shield, cleaver, topknot, brass ring, teal scarf and stone armour, is confirmed by a reviewer looking at the capture, with a one-line reason.

The old browser version measured the background as well as the character, which made its colour numbers unreliable. The new version also renders a mask of the same shot and measures only the character's own pixels.

Passing all three checks only moves a row to "ready for the team". A row still passes only when every framing gets a 9 or 10 from the team. Each row will show the bible crop and the Unity capture side by side, with the commit and the capture time, and will be marked out of date when the game has changed since its capture.
