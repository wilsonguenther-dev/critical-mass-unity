- ADVISORY R20261112T1705-1-1: F-02a Assets/_Game/Sim.Tests/BoundaryTests.cs:25 The guard only catches the fully qualified `System.Random`. A Sim file with `using System;` (JsMath.cs, Rng.cs's neighbours, World.cs, FlowField.cs all have it) can call `new Random(...)` or `Random.Shared` and pass. `DateTimeOffset.Now`, `DateTime.Today` and `GetHashCode` (randomised per process on .NET) are also not caught. The builder followed the F-02a spec list, so the gap is in the spec. Recommend: an item that adds `\bnew\s+Random\s*\(`, `\bRandom\s*\.\s*Shared\b`, `\bDateTimeOffset\b`, `\bDateTime\s*\.\s*Today\b` and `\bGetHashCode\s*\(` to Banned, plus a TheGuardItselfCatchesAViolation case for an unqualified `new Random()`. Land it before F-05/F-06 port the bulk of the Sim.
- ADVISORY R20261112T1705-1-2: F-04 Assets/_Game/Sim/Grid/SpatialHash.cs:59 CellOf (lines 59-64) and QueryCircle (lines 105-117) clamp the result of JsMath.FloorToInt. For +Infinity, or any finite coordinate/cellSize beyond int range, FloorToInt returns int.MinValue, which clamps to cell 0. The browser's Math.floor gives +Infinity, which clamps to cols-1/rows-1. So a runaway position is bucketed at the opposite edge, and a query with a huge or infinite radius scans only column/row 0 instead of the whole grid. No current browser caller passes such values (fsm.ts, steer.ts, collide.ts, combat.ts all use finite small radii), so outcomes match today. Recommend: compare the double against 0 and cols before converting, e.g. `double f = Math.Floor(x / cs); int cx = !(f >= 0) ? 0 : f >= h.Cols ? h.Cols - 1 : (int)f;` (NaN goes to 0, the same as now). Same fix for c0/c1/r0/r1.
