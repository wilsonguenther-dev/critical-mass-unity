# F-02c JsMath transcendentals (fdlibm) and the Sim ban

Conventions apply (rule 6.15 as rewritten by U-032). Added by the architect on 2026-11-12 (U-032, panel deferred list):
the browser oracle runs under node, and node's V8 computes `Math.sin`, `Math.cos`, `Math.atan2` and `Math.exp` with its
own fdlibm port (`src/base/ieee754.cc`; node builds V8 without `V8_USE_LIBM_TRIG_FUNCTIONS`, checked in node's
`tools/v8_gypfiles` on 2026-11-12, so sin and cos are fdlibm too). `System.Math` calls the platform C library, which
differs from fdlibm in the last bit on some inputs. map.ts compares `atan2` angles with `<=`, so one last-bit
difference can change a discrete choice. This item makes the four functions bit-exact with node.

It is the first item of batch 2 and sits in batch 2's coupled set (every F-05 item waits on it). Its API exists for
the F-05 builders through the upstream contract (P-06): call `JsMath.Sin`, `JsMath.Cos`, `JsMath.Atan2`, `JsMath.Exp`.

## Port from

| Source | What |
| --- | --- |
| V8 `src/base/ieee754.cc` at tag `13.6.233.10` (the V8 of node v24.11.1, which made the golden file): `curl -sL https://raw.githubusercontent.com/v8/v8/13.6.233.10/src/base/ieee754.cc` | `__ieee754_rem_pio2`, `__kernel_rem_pio2`, `__kernel_sin`, `__kernel_cos`, `sin`, `cos`, `atan`, `atan2`, `exp`, the tables `two_over_pi`, `npio2_hw`, `init_jk`, `PIo2`, and the macros `GET_HIGH_WORD`, `GET_LOW_WORD`, `EXTRACT_WORDS`, `INSERT_WORDS`, `SET_HIGH_WORD`, `SET_LOW_WORD` |
| `tools/golden/jsmath-fdlibm.json` (committed by the architect; generator `tools/golden/gen-jsmath.mjs`) | 2,038 `sin` and 2,038 `cos` vectors, 2,029 `exp`, 2,081 `atan2`; inputs and outputs as 16-hex-digit IEEE-754 bit patterns |

The V8 file is read for the port only; the C# keeps the Sun copyright notice block from the top of that file at the
top of `Fdlibm.cs` (the fdlibm licence requires it).

## Create

**`Assets/_Game/Sim/Core/Fdlibm.cs`** (namespace `CriticalMass.Sim.Core`): `internal static class Fdlibm` with
`public static double Sin(double x)`, `Cos(double x)`, `Atan2(double y, double x)`, `Exp(double x)` and the private
helpers `RemPio2(double x, double[] y)` (returns `int n`), `KernelRemPio2(double[] x, double[] y, int e0, int nx, int prec)`,
`KernelSin(double x, double y, int iy)`, `KernelCos(double x, double y)`, `Atan(double x)`. Port line by line, same
constant literals (copy the hex-float comments too), same branch order, same operation order in every expression.

- Word access: `long b = BitConverter.DoubleToInt64Bits(x); int hi = (int)(b >> 32); uint lo = (uint)b;` and back with
  `BitConverter.Int64BitsToDouble(((long)hi << 32) | lo)`. `GET_HIGH_WORD` gives an `int`, `GET_LOW_WORD` a `uint`,
  exactly as the C `int32_t` / `uint32_t` declarations in ieee754.cc.
- Every expression keeps the C association: never fold, reorder, factor, use `Math.FusedMultiplyAdd`, nor call any
  `System.Math` function except `Math.Abs` (fabs), `Math.Floor` (floor, used by `__kernel_rem_pio2`) and
  `Math.Sqrt` (not needed here; listed because it is correctly rounded on every platform).
- `volatile` locals and `tiny` / `huge` constants of the C code (flag raising) are kept as plain `double` values in
  the same expressions: `huge + x > one` style tests keep their result.
- `exp`: keep V8's added line `if (x == 1.0) return E;` with `E = 2.718281828459045` (V8's own fix for exp(1)).
- `__kernel_rem_pio2`: the work arrays `iq[20]`, `f[20]`, `fq[20]`, `q[20]` are `new int[20]` / `new double[20]`
  per call (no shared static scratch: tests run single-threaded, but a fresh array keeps the port obviously equal).
- Integer arithmetic of the C code (`int32_t`, `uint32_t`, shifts) uses `int` / `uint` in `unchecked` blocks with
  the same signedness as the C declarations.

**`Assets/_Game/Sim.Tests/JsMathFdlibmTests.cs`** (namespace `CriticalMass.Sim.Tests`, `public sealed class JsMathFdlibmTests`,
**new, no vitest twin**): reads `tools/golden/jsmath-fdlibm.json` with `File.ReadAllText` from the project root (the
EditMode working directory, as `BoundaryTests` does). Parsing, exactly: the file is one JSON line with keys in the
order `generator, node, v8, note, sin, cos, exp, atan2`; take the text between `"sin":` and `"cos":` for sin, between
`"cos":` and `"exp":` for cos, between `"exp":` and `"atan2":` for exp, and from `"atan2":` to the end for atan2; in
each slice every vector is a match of `\["([0-9a-f]{16})","([0-9a-f]{16})"(?:,"([0-9a-f]{16})")?\]`. Bits to double:
`BitConverter.Int64BitsToDouble(unchecked((long)Convert.ToUInt64(h, 16)))`. Compare: when the expected value is NaN,
`double.IsNaN(actual)`; every other expected value must equal `BitConverter.DoubleToInt64Bits(actual)` bit for bit
(so `-0` is not `+0`). Each of the four function tests collects every mismatch and fails once, listing the count and
the first 20 as `input hex -> expected hex, got hex`.

## Behaviour notes

- V8's main branch has since moved these functions to LLVM libc (`LIBC_NAMESPACE::shared::sin`); the oracle is pinned
  to the node that ran the browser tests, so the port follows tag 13.6.233.10 and the golden file records the node
  version. A future node upgrade regenerates the golden file through the architect, never through a builder.
- `Math.Sqrt`, `Math.Floor`, `Math.Ceiling`, `Math.Abs`, `Math.Min`, `Math.Max` stay `System.Math`: they are exact in
  IEEE-754 on every platform, the same as V8.
- `Math.hypot` appears only in browser test files (never in sim, bots); nothing to port.
