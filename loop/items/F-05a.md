## Create (namespace `CriticalMass.Sim.Core`)

(browser `emptyInput`, `applyInput`). `EmptyInput` returns all zero, `ClassPick = -1`, `Jump = false`, `Terraform = false`.
`ClassPick` -1 means none; 0..4 is a `ClassId`.

the airborne branch: one marker each, `// ITEM CM-32: added by its owner (jump read/clear)`, `(jump takeoff)`,

## Behaviour notes

- `applyInput`, exactly (input.ts lines 9-34): an out-of-range `actorId` returns; when one move component is non-finite
  both become 0; a move longer than 1 is scaled by `1 / Math.Sqrt(len2)`; `HasAim[id] = 1` only when both aim components
  are finite, and a non-finite aim stores the actor's own `X[id]`, `Z[id]` as `AimX`, `AimZ`; booleans copy as `== true`;
  `ClassPick` is kept only when `0 <= cp < 5` (the TS `Number.isInteger` check is implicit for an `int`), else -1.
- `EmptyInput()` has `AimX = AimZ = 0`, which is FINITE: applying it sets `HasAim = 1` aimed at the world origin. "No
  aim" is a NaN aim, never an empty frame.
- Movement writes `Vx`/`Vz`/`X`/`Z` as `double`; the browser's Float32 write is dropped (conventions 6.1).
- The movement step calls `Collide.MoveActor(w, id, dx, dz, false)` (F-05b) where the browser calls `moveActor`.
