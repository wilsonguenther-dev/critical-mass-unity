# A-04 Kaiju art

Added by the architect on 2026-11-12 (U-043, owner ruling: all art is made by us in Blender, by script; no art waits
on Max). Owner: the loop (orchestrator), never Max (U-045 keeps Max on his mechanics items only).

## Base

Branch `art/warrior-blender` (a separate agent builds the Blender project and the Warrior there) sets the layout this
item follows: its shared rig module, its palette module (the bible swatches as named constants), its build-script
entry point and its export settings. This item adds the Kaiju beside the Warrior at the same relative paths and imports
the shared modules; it never copies, forks, edits them. The batch holding this item launches only after that branch is
on main (`_ORDER.md` batch 5).

## Create

- The Kaiju's Blender build script under `tools/blender/kaiju/`: builds the mesh from code (U-043 replaces U-009's
  "sculpted by a person"), binds it to the Kaiju rig the Warrior branch's rig module defines for quadrupeds (U-043 open question 2), writes the `TeamMask` vertex colour layer (red = 1 on the team parts
  the bible page names) and the region colours from the palette module, and exports FBX to
  `Assets/_Game/Art/Kaiju/Kaiju/` with the Warrior's export settings.
- The `.blend` the script saves, in `Assets/_Game/Art/Kaiju/_source~/Kaiju/` (Git LFS; Unity skips `~` folders, P-08),
  with a build note naming the script, the Blender version (5.2.3, U-022) and the command line.

## Check

The parity gate for row p10 (CM-KAI-001 and CM-KAI-002, bible p10 and p11): colour within ΔE2000 10 per named swatch, silhouette IoU at least 0.85, every
required feature on the row's checklist confirmed (PARITY.md sections 4 and 6). Shading is `CM/Toon` only (V-01).

## Out of scope

The Warrior (branch `art/warrior-blender`); animation clips beyond what the shared rig already carries; gameplay
code; any Max item.
