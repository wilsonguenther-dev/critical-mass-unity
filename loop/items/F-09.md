`maxSteps = (int)Math.Ceiling(MatchSeconds * SimHz) + SimHz`, and drives each tick with `MatchTick.Advance`: `Bot` passes
`null` to `MatchTick.Advance`; `Passive` calls `MatchTick.AdvanceNoHuman(w, scratch)` (actor 0 gets no input at all, browser

`ang = 2 * Math.PI * w.Match.Time / WanderPeriod; f.MoveX = Math.Cos(ang); f.MoveZ = Math.Sin(ang);` (one full circle every
`WanderPeriod` seconds, outcomes.ts lines 66-71). The loop runs `for (s = 0; s < maxSteps && w.Match.Phase != MatchPhase.Ended; s++)`.

## Behaviour notes

- Sampling is once per sim second, not every tick: after each tick `if (w.Tick % SimHz != 0) continue;`; duty is sampled
  for `DutyFrom - 1e-6 <= t <= DutyTo + 1e-6`; shares only for `t > OutcomeSampleFrom + 1e-6`. `OwnerChanges` counts a
  change of `HillState` between `Azure` and `Crimson` samples (contested and neutral samples do not reset `lastOwner`).
  `round1(v)` = `JsMath.Round(v * 10) / 10`. `OwnedShare` = `owned / samples` (0 when no samples), a `double` division.
- `MatchOutcome.DeliveredBiomass` / `DeliveredCorruption` hold the browser `delivered.{azure,crimson}` and
  `delivered.{corruptionAzure,corruptionCrimson}`; `Hatch` is the `Kaiju.State` on the first tick `Match.Hatched` is true.
- These bands are the long-run oracle (U-002): counts and outcomes must match the browser's bands, not its per-seed
  values (Float32 drift over 14,400 ticks can change a seed's winner; O-01).
